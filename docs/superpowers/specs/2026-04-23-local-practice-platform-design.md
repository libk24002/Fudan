# 本地练题与自动归档平台设计

## 目标

在现有 C 练习仓库上增加一个本地单用户 Web 平台，支持题目提交、在线沙箱练习、AI 评审与自动归档，降低手工维护仓库成本，并提升检索与复习效率。

## 约束与决策

- 单用户，本地运行（localhost）。
- 沙箱语言仅支持 C、C++、Java。
- 沙箱安全优先，采用 Docker + gVisor(runsc)。
- 用户先完成练习后才可查看 AI 参考解（防剧透）。
- 两按钮流：
  - `确认结束`：结束本题练习阶段。
  - `归档入库`：触发 AI 分析并写入仓库。
- 仓库中的 `solution.c` 使用 AI 参考实现，不直接收录用户代码。
- 必须收录用户解题思路摘要。
- 不做多用户与远程部署。

## 核心流程

1. 用户提交题目，系统创建练习会话（created）。
2. 用户在沙箱中反复编译运行（practicing）。
3. 用户提交最终代码与解题思路，并点击 `确认结束`（finished）。
4. 用户点击 `归档入库`，系统触发 AI 生成参考解并审查用户思路（archiving）。
5. 审查通过后落库并更新索引（archived）。

## 状态机

- `created -> practicing -> finished -> archiving -> archived`
- 失败回退：`archiving -> practicing`
- 归档前置：必须先 `finished`，且 AI 结果为 `PASS`。

## 仓库产物规范

每题目录：`problems/<module>/<problem-slug>/`

- `solution.c`：AI 参考实现。
- `README.md`：题意、AI 标准思路、用户思路摘要、边界条件、复杂度、首次完成日期、最后修改日期。
- `meta.yaml`：检索元数据。
- `review.md`：AI 评审结论与建议。

索引目录：

- `index/by-module.md`
- `index/by-c-topic.md`

## 质量门禁

- AI 评审必须输出结构化结果：`PASS/FAIL` + 问题列表 + 建议。
- 仅 `PASS` 允许归档。
- 归档时检查题目目录完整性与元数据必填字段。

## 错误处理

- 编译失败：返回编译错误，不进入运行。
- 超时/OOM：标准化错误码并提示。
- 沙箱异常：不中断会话，状态回退 `practicing`。

## 测试策略

- 后端：路由、状态机、归档门禁、索引生成测试。
- 沙箱：语言支持、超时、内存限制、禁网验证。
- 前端：两按钮流程、状态切换、执行结果展示。
